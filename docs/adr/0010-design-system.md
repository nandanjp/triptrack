# ADR-0010 — Tailwind with hand-owned shadcn-style components, and a token layer for theming

**Status:** Accepted · 2026-10-04

## Context
Seven steps shipped the domain behind inline `style` objects — about 150 of them. That
was the right trade while the shape was unsettled, but it had stopped paying: no theming,
no reuse, and every new view re-deriving its own spacing and colour.

The brief asked for a Notion-like application with shadcn components, considered
typography and colour, and light and dark mode.

Alternatives considered:

- **Plain CSS modules or vanilla CSS.** No dependencies, and theming via custom
  properties works fine. Rejected because every component would carry its own stylesheet
  and the variant logic (a button with five looks and four sizes) ends up hand-rolled.
- **A component library used as a dependency** — MUI, Mantine, Chakra. Fastest to
  assemble and the hardest to make not look like itself, which is the opposite of the
  brief.
- **Hand-written components in shadcn's idiom.** Tried first, on the assumption that the
  CLI would not cope with this layout. It copes fine: a `components.json` pointing its
  aliases at `web/src` is all it needed, and the generated components are better than the
  imitations — they carry `data-slot` hooks, `asChild`, variants this project had not
  thought to want, and they stay upgradeable.
- **Tailwind plus components generated by the shadcn CLI.** Chosen.

## Decision
Tailwind v4 through its Vite plugin, with CSS-first configuration — no
`tailwind.config.js`.

`web/src/ui` holds components **generated by the shadcn CLI and left alone**, so
`npx shadcn add` keeps working and upstream fixes can be pulled in. `web/src/components`
holds this application's compositions on top of them — a labelled field, a flat panel, a
labelled checkbox, an option list over `Select`, the mobile sheet, the theme switcher.
That split is the point: the generated layer stays replaceable, and anything specific to
trips lives beside it rather than inside it.

Colour and type keep **shadcn's token names** rather than this project's earlier ones.
That is what makes a freshly generated component look right immediately, and it corrected
a real mistake: in shadcn's vocabulary `--accent` is a subtle hover surface and
`--primary` is the brand. Having those the other way round would have flooded every
ghost button with the brand colour.

Colour and type are a **two-layer token system**: plain custom properties on `:root` and
`:root.dark` hold the values, and `@theme inline` maps them onto Tailwind's scale. That
is what makes `bg-raised` or `text-muted` mean the right thing in both themes without a
single `dark:` prefix in application code.

Theme preference is `light | dark | system`, stored in `localStorage`, applied as a class
on `<html>` by an inline script **before first paint** so a dark-mode reload does not
flash white. `system` keeps tracking the OS after load rather than reading it once.

Fonts are self-hosted via `@fontsource`, not linked from Google.

## Consequences
- **Dark mode is a design, not an inversion.** Dark surfaces are a cool slate and the
  accent lightens to hold its contrast against them, which means two palettes to keep in
  step rather than one. A new colour has to be added in three places: both `:root`
  blocks and the `@theme` map.
- **Self-hosted fonts cost 0.29MB in the image** and remove every external request from
  the render path — the app looks right on bad hotel wifi, and nothing on the critical
  path leaves the cluster. The deployed amd64 image is still dominated by the Node
  runtime; application content is 1.8MB in total.
- **Selects are now Radix rather than native.** The earlier hand-written set kept a
  native `<select>` so a phone would open the platform picker. Using shadcn's means
  giving that up, in exchange for consistent styling and one component to reason about.
  Worth revisiting if it reads badly on a phone.
- **`cn` is a dependency, not a local helper.** The CLI pulls `cn` — shadcn's own package
  — in place of `clsx` plus `tailwind-merge`, so this project follows it rather than
  patching every generated file.
- **Generated files need one edit**: `nodenext` resolution requires the extension on
  `@/ui/button`, which the CLI omits. That has to be reapplied after each `shadcn add`.
- **Tailwind v4's CSS-first config is young.** There is less written about it than about
  v3's JavaScript config, so an unusual need may be harder to look up.
- **No component tests.** The suite covers the server; these components are unverified by
  anything but typechecking, a build and a human looking at them. That is a real gap, and
  the reason this change was kept to presentation with no behaviour touched.
- **Loading states are deferred, not immediate.** Most loads here finish in tens of
  milliseconds, so a placeholder shown at once appeared and vanished — worse than nothing.
  Nothing renders for 300ms; past that the wait is long enough that a placeholder
  reassures rather than flickers. Verified both ways: a normal load renders no placeholder
  at all, and a load slowed to 900ms does show one.
- **Reviewed in a browser, light and dark, desktop and phone.** That pass caught four
  things reasoning had not: a vanished day spine, an active-tab box, a two-up totals row
  collapsing to one column, and the loading flash below.
